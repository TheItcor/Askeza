Askeza - язык программирования с виртуальными регистрами и стеком как центральной системой структуры данных, интерпретируется через виртуальную машину VSMI (Virtual Stack Machine Interpreter).

На данном этапе язык интерпретируемый, позже планируется возможный переход на компиляцию.

Логика версий: число.число.число "название"  пример: 1.0.0 "Socrates"  
├─ X: MAJOR (большие изменения) - может сломать совместимость  
├─ Y: MINOR (новые возможности)
└─ Z: PATCH (новые исправления)


**Особенности:**
- Стек на 1024 элементов (по умолчанию)  
- Виртуальные 4 регистра (по умолчанию)  
- Интерпретируемый
- Конкатенативный  
- Поддерживает три типа данных: char, integer, float


Догматы (принципы) языка:
1. Работа в стеке ведётся исключительно с верхними элементами стека.  
2. Возвращаемое значение всегда будет уходить на специальный регистр.  
3. Код не должен быть избыточным.  
4. Код должен оставаться читабельным.  
5. Одна инструкция - одно действие.

# Интерпретатор

Интерпретатор скомпилированный из .c файла работает по следующей схеме:
Чтение построчно файла -> дробление на токены -> просчитывание инструкций и аргументов -> непосресдтвенное выполнение

Запуск файла:
```
ask main.ask
```

Запуск файла с отладкой:
```
ask -d main.ask
```

Изменить размер стека в элементах (по умолчанию 1024 элементов):
```
ask s2048 main.ask
```

Изменить количество регистров (по умолчанию 4 регистра):
```
ask r8 main.ask
```

все параметры:
```
ask (вкл дебаггер) (размер стека) (кол-во регистров) (файл.ask)
```

## Деббагер

## Ошибки интерпретатора

* [Syntax Error] - Синтаксическая ошибка.
* [Read Error] - Ошибка при чтении файла.

| `[Fatal Error][line]: Stack underflow`                       | Стек опустошен. Указатель стека провалился за нижние ограничения. |

# Стек и регистры

Стек - центральная структура данных, рабочая память для виртуальной машины. Все вычисления происходят через операции на вершине этой структуры (LIFO). Размер по умолчанию 1024 элементов по 4 байтов каждый. 


В Askeza всего 4 (5) регистра:
- r0, r1, r2, r3. Все они могут хранить только одно значение до 4 байтов. Это не настоящие регистры процессора как в assembly, а лишь их виртуальная реализация. 
- rr (return register) - регистр куда предлагается возвращать результат выполнения функций-меток.

Элемент стека или регистр могут хранить следующие типы данных:
- int (4 байт)
- char (1 байт)
- float (4 байт)

### Синтаксический сахар

#### push
Можно отправлять в стек сразу несколько элементов или даже целые "строки":

```
push s 10 20 30 40 
```
В этом случае 10 - будет на дне стека, а 40 наверху стека.

```
push s 'cat'
```
В стек будет отправлено 't' 'a' 'c', где 'c' - будет наверху стека. Т.е. слово будет записано в стеке задом-наперёд.

#### print
помимо вывода одного элемента:
```
push r0 'a'
push s 'b'

print r0 // --> a
print s  // --> b
```

можно выводить кусками из стека:
```
push s 20 10 40

print s 3
```
Отправляем на стек 3 числа и выводим последние 3 элемента на стеке. Вывод начнётся с самого верхнего числа "40".

Вывод "строки":
```
push s 'Hello'

print s 5
```
Отправляем на стек 5 символов и выводим последние 5 элемента на стеке. В стек запишится: 'o','l','l','e','H', а выведется: 'H','e','l','l','o'.





## Метки, безусловный переход, вызов подпрограмм, возврат
Нет привычного понимания функции как в высокоуровневых языках. Вместо этого есть метки, возвраты и переход. 
Для объявление метки нужно написать `название_метки:`. Пример:

Перепрыгивание к метке (бесконечный цикл):
```
loop:
    push r0 1
    add r0 r0
    print r0
    jmp loop       // вернуться на метку loop
```


Вызов подпрограммы. Работает как jmp, но перед переходом запоминает адрес следующей инструкции в специальном стеке вызовов.
Когда внутри подпрограммы выполнится ret, управление вернётся к инструкции, идущей сразу после call.

```
double:
    mul r0 2
    push rr r0     // сохранить результат в return-регистр
    ret            // вернуться к точке вызова

main:
    push r0 5
    call double    // перейти к double, запомнив точку возврата
    print rr       // напечатает 10
    end 0
```




Другие примеры:
```
print_hello:
    // using stack       // Предупреждаем, что функция будет работать только со стеком
    push s 'hello world' // будет отправлено на стек как 'h', 'e', 'l'...
    print s 11           // вывести в консоль последние 11 элементов
    
    
main:
    jmp print_hello
```


```
print_two:
    // using r0, rr  // Предупреждаем о работе r0, rr в метке
	add r0 2
	push rr, r0 // перемещаем значение из r0 в rr 
	ret         // возвращаемся


main:
    jmp two
```

## Циклы
С помощью меток вы можете создать циклы:

Реализация цикла for
```
main:
    push r0 0
    
for:

    // тело цикла
    add r0 1
    if (r0 != 10); jmp for; jmp end_for

end_for:
    // продолжение
```

Реализация цикла while
```
main:
    push r0 0

loop:

    // тело цикла
    if (r0 = 1); jmp loop; jmp end loop

end_loop:
    
    // продолжение
```

# Импорт других файлов
В Askeza можно импортировать код из других файлов. При импорте импортируются из файла только метки, кроме `main`.


файл lib.ask
```
square:
    // use r0, rr
    mult r0 r0
    ret rr

main:
	push r0 2
	jmp squre
	print r0
	end 0
```

файл main.ask
```
import "lib.ask"

main:
	  push r0 10
    call squre
    print rr
    end 0
```
Вывод:
`100`

Будьте готовы к тому, что во время выполнения функций ваши регистры/стек могут поменять значения. В особенности регистр `rr` (return register).



# Рекомендации к оформлению код

## Оформление функций

- Название функций должно быть в snake_style.
- Если метка что-то возвращает, то должна это возвращать в специальный регистр rr (return register)

## Отступы

- Рекомендовано делать 4 пробела после метки в том числе main:
```
main:
    push s 'hello, world!'
    print s 13

```

* между метками (в том числе main) должен быть 1 отступ
```
main:
	if (r0 != 0); jmp then;

then:
    jmp print_cool
```
